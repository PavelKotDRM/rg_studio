# Руководство пользователя rg studio

[English version](user-guide.en.md) · [README проекта](../README.md)

rg studio — графический конструктор команд для
[ripgrep](https://github.com/BurntSushi/ripgrep). С его помощью можно настроить
поиск, проверить собранную команду, запустить CLI ripgrep и просмотреть
результат. Исполняемый файл ripgrep не входит в приложение.

## Установка и запуск

Для сборки из исходного кода установите [Rustup](https://rustup.rs/) и stable
toolchain Rust:

```powershell
rustup update stable
cargo run --release
```

CLI ripgrep устанавливается отдельно. Рекомендуется версия 15.2.0: на ней
основан каталог параметров приложения. При нажатии **Run ripgrep** приложение
ищет `rg.exe` или `rg` рядом со своим исполняемым файлом, затем в родительской
папке этого файла и, наконец, в `PATH`.

## Настройка поиска

### Шаблон и путь

- **Search pattern** — регулярное выражение для содержимого файлов, а не маска
  имени файла. Например, `*.` — некорректное выражение: `*` должен повторять
  предшествующий элемент. Для любых символов в строке используйте `.*`. Чтобы
  отфильтровать имена файлов, включите **Include/exclude glob** в категории
  **Files** и введите маску, например `*.rs`. Для точного текста включите
  **Literal strings** в категории **Search**.
- В поле **Search in** укажите файл или каталог. Если оставить поле пустым,
  ripgrep ищет в текущем рабочем каталоге; значение `.` явно задаёт этот каталог.
- В сгенерированной команде путь передаётся после `--`, поэтому путь,
  начинающийся с `-`, будет воспринят как путь, а не как параметр.

### Категории параметров и фильтр

Каталог параметров разделён на категории **Search**, **Files**, **Output** и
**Modes & diagnostics**. Отметьте флажок, чтобы добавить параметр в команду.
Поле значения показывает ожидаемый тип: поля glob принимают маски файлов,
а основное поле шаблона — регулярное выражение.

Фильтр **Filter options** ищет как по названию параметра, так и по имени флага.
Он меняет только отображаемые карточки и не сбрасывает выбранные параметры.

Разверните **Advanced arguments**, чтобы ввести повторяемые параметры или
флаги, которых нет в каталоге. Строка разбирается на аргументы командной
строки; значения в кавычках остаются одним аргументом. Если кавычки не
сбалансированы, приложение покажет ошибку и не даст запустить команду.

Кнопка **Run ripgrep** запускает CLI напрямую, без shell. Поэтому операторы
shell, например `|`, здесь не выполняются как команды shell. Однако параметры
ripgrep, такие как `--pre`, сохраняют собственное поведение ripgrep; указывайте
для них только доверенные значения.

## Создание регулярного выражения

Нажмите **Regex builder** рядом с полем шаблона, чтобы открыть визуальный
редактор. Если в поле уже есть выражение, оно будет импортировано как часть
**Raw regex**, чтобы сохранить исходный текст.

1. Добавьте атом или выберите тип для существующей строки. Доступны, например,
   буквальный текст, raw regex, любой символ, цифра, буквенно-цифровой символ,
   пробельный символ, классы символов, группы, граница слова и альтернатива.
2. При необходимости введите значение атома. Буквальный текст экранируется
   автоматически. Для класса символов укажите его содержимое (например,
   `a-z0-9`); скобки добавит конструктор.
3. Выберите квантификатор: один раз, необязательный (`?`), ноль или более (`*`),
   один или более (`+`), точное количество (`{n}`) или диапазон (`{min,max}`).
4. Используйте **Start of line** и **End of line**, чтобы добавить `^` и `$`.
   Кнопки **Up**, **Down** и **Remove** позволяют менять порядок строк и удалять
   их; **Clear** удаляет все строки.

Поле **Generated regex** доступно только для чтения. Конструктор проверяет
выражение стандартным Rust regex-движком и показывает ошибку, если выражение
некорректно.

## Предпросмотр и реальный поиск

В блоке **Live text preview** можно редактировать тестовый текст и сразу
видеть подсвеченные совпадения. Нажмите **Hide** или **Show**, чтобы свернуть
или развернуть блок.

Предпросмотр намеренно не является полноценным запуском ripgrep: он проверяет
только основной шаблон на введённом тексте. Он не ищет в файлах, не читает
файлы шаблонов, не применяет ignore-файлы и glob-фильтры и не воспроизводит все
параметры ripgrep. Учитывается только часть настроек регулярных выражений,
например регистр, поиск буквальной строки, многострочный режим, Unicode и
совпадение целого слова или строки.

При выборе PCRE2 или движка `auto` предпросмотр недоступен. Эти режимы всё ещё
можно использовать для реального поиска, если их поддерживает установленная
сборка ripgrep.

Для поиска по файловой системе проверьте блок **Generated command** и нажмите
**Run ripgrep**. CLI запускается в фоне. Окно результатов поясняет, завершился
ли поиск успешно, не нашёл совпадений или сообщил об ошибке; также показывает
код завершения, время выполнения, исполняемый файл и запущенную команду.
Результаты (`stdout`) и сообщения (`stderr`, например предупреждения и ошибки)
по умолчанию показываются в режиме **CLI output** с отдельным выбором `stdout`
и `stderr`. Страницы позволяют просматривать большой вывод; копируется
текущая страница; длинные строки переносятся по ширине окна. В команду попадают
только явно выбранные параметры. Форматы,
изменённые параметрами ripgrep (например, JSON, счётчики, контекст или список
файлов), показываются без преобразования; текст совпадений подсвечивается,
когда он есть в потоке. ANSI-цвета отображаются, но при копировании исходные
последовательности сохраняются. При `--color=auto` совпадение подсвечивается,
даже если перенаправленный `stdout` не содержит ANSI-кодов. Невалидные UTF-8
байты показываются как `\xNN`, обратные слеши удваиваются для восстановления
без потерь. Файлы `.d` могут содержать много путей в одной строке. Код
завершения `1` означает, что совпадений нет; это нормальный результат ripgrep,
а не ошибка приложения.

Нажмите **Copy command**, чтобы скопировать отображаемую команду для запуска в
терминале. Шаблон, путь и выбранные значения параметров экранируются с учётом
текущей ОС.

## Решение проблем

- **Unable to start ripgrep:** установите CLI, положите его рядом с приложением
  (или в родительскую папку) либо добавьте его в `PATH`.
- **Enter a pattern or select a patternless ripgrep mode:** введите шаблон или
  выберите режим, которому он не требуется, например **List searchable files**
  в категории **Modes & diagnostics**.
- **No matches (exit code 1):** проверьте шаблон, путь и включённые фильтры.
  Код `1` означает, что поиск завершился без совпадений.
- **Invalid regex:** **Search pattern** — регулярное выражение, а не маска
  имени файла. `*.` некорректно: `*` должен идти после выражения; используйте
  `.*` для любых символов в строке. Для маски имени файла откройте **Files** >
  **Include/exclude glob** и укажите, например, `*.rs`. Стандартный Rust
  regex-валидатор не принимает синтаксис, специфичный для PCRE2.
- **ripgrep отклоняет параметр:** проверьте, поддерживает ли его установленная
  версия CLI. Каталог рассчитан на ripgrep 15.2.0; для отсутствующих в нём
  параметров используйте **Advanced arguments**.
