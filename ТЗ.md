# Техническое задание: Графический конфигуратор команд ripgrep (ripgrep GUI Composer)

## 1. Общее описание проекта
Разработка кроссплатформенного графического приложения (GUI), предоставляющего удобный визуальный интерфейс для утилиты командной строки `ripgrep` (`rg`). Приложение предназначено для визуального конструирования сложных команд поиска с поддержкой полного функционала `ripgrep`. Главная задача приложения — позволить пользователю легко выбрать необходимые параметры поиска через графические элементы управления, сгенерировать корректную команду и скопировать её в буфер обмена для последующего использования в командной строке.

## 2. Технологический стек
* **Язык программирования:** Rust (строго последняя стабильная версия на момент начала разработки).
* **Графический фреймворк:** `egui` (последняя актуальная версия).
* **Генерация информации о сборке:** `vergen` (строго версии 10.x).
* **Система сборки и управления пакетами:** `cargo`.

## 3. Требования к инициализации проекта
Перед написанием кода и на этапе создания проекта необходимо выполнить строгую проверку зависимостей:
1. Убедиться, что установлена самая свежая версия тулчейна Rust (`rustup update stable`).
2. Проверить на *crates.io* и зафиксировать в `Cargo.toml` последние версии всех необходимых модулей, в первую очередь `egui`, `eframe` (если используется как интеграция для `egui`), и других вспомогательных крейтов.
3. Добавить зависимость `vergen` версии 10 в `[build-dependencies]`.

## 4. Функциональные требования
* **Визуальный конструктор команд:** Приложение должно предоставлять элементы интерфейса (чекбоксы, выпадающие списки, текстовые поля) для каждого флага и аргумента, поддерживаемого актуальной версией `ripgrep`.
* **Генерация в реальном времени:** При любом изменении состояния UI (включение флага, ввод текста), результирующая строка с командой `rg ...` должна обновляться мгновенно.
* **Копирование команды:** Наличие большой, легкодоступной кнопки **Copy to Clipboard** для копирования итоговой команды.
* **Категоризация настроек:** Полный функционал `ripgrep` должен быть логически разделен на вкладки или раскрывающиеся секции (например: *Basic Search*, *File Filtering*, *Output Formatting*, *Performance/Limits*).
* **Раздел About (О программе):** Отдельное окно или вкладка, отображающая детальную информацию о текущей сборке программы.
  * Для генерации данных о сборке **обязательно** использование крейта `vergen` версии 10.
  * Выводимая информация должна включать: версию программы, хеш коммита, дату сборки, версию компилятора Rust, целевую платформу (target).

## 5. Требования к пользовательскому интерфейсу
* Интерфейс строится исключительно на базе фреймворка `egui`.
* **Макет (Layout):**
  * *Верхняя панель:* Строка поиска (Pattern), выбор директории (Path).
  * *Левая/Центральная панель:* Сгруппированные опции `ripgrep` (например: `-i` Ignore Case, `-w` Word Match, `-v` Invert Match, скрытые файлы, фильтрация по типу файлов и т.д.).
  * *Нижняя панель:* Поле с предпросмотром сгенерированной команды (только для чтения) и кнопка копирования.
* Поддержка светлой и темной темы (стандартные возможности `egui`).

## 6. Требования к качеству кода и проверкам
Для обеспечения высокого качества кода должен использоваться весь встроенный функционал Rust и экосистемы `cargo`. Все инструменты должны быть интегрированы в рабочий процесс и упомянуты в документации.
* **Форматирование:** Код должен быть отформатирован с помощью `cargo fmt`.
* **Линтинг:** Отсутствие предупреждений при проверке `cargo clippy -- -D warnings`. Необходимо использовать строгие правила линтинга.
* **Безопасность и аудит:** Регулярная проверка зависимостей через `cargo audit` (или `cargo-deny`).
* **Документирование кода:** Каждая публичная функция и структура должна быть задокументирована с использованием внутрикодовой документации (`///`). Проверка через `cargo doc`.

## 7. Требования к ведению документации (README.md)
Файл `README.md` является центральным элементом управления проектом и должен содержать следующую структуру:
1. **Название и описание:** Краткая суть приложения.
2. **Требования и запуск:** Инструкции по установке тулчейна и сборке приложения.
3. **Отслеживание прогресса (Progress Tracker):** Весь процесс разработки должен отображаться в `README.md` в виде интерактивного чек-листа (To-Do списка). Каждая новая фича или исправленный баг отмечаются галочками `[x]`.
4. **Обеспечение качества (Quality Assurance):** Отдельный обязательный раздел, в котором подробно описано использование всего функционала Rust для проверки качества кода. В этом разделе должны быть явно указаны команды:
   * `cargo fmt --all -- --check`
   * `cargo clippy --all-targets --all-features -- -D warnings`
   * `cargo test`
   * `cargo audit`
5. **Используемые технологии:** Указание версий Rust, `egui` и `vergen`.

## 8. Этапы реализации (Roadmap)
Для корректного отражения прогресса в `README.md`, разработка делится на следующие шаги:

* **Этап 1: Инициализация**
  * Проверка последних версий зависимостей.
  * Создание базовой структуры `cargo new`.
  * Настройка скрипта сборки `build.rs` для `vergen` (v10).
  * Настройка первоначального `README.md` с трекером задач.
* **Этап 2: Базовый UI и "About"**
  * Интеграция `egui` и запуск пустого окна.
  * Реализация вкладки/окна **About** с выводом данных от `vergen`.
* **Этап 3: Базовый функционал ripgrep**
  * Создание полей ввода для Pattern и Path.
  * Добавление основных флагов (Case sensitive, Word match, Line number).
  * Динамическая генерация строки команды и кнопка "Copy".
* **Этап 4: Расширенный функционал**
  * Реализация вкладок для всех остальных параметров `ripgrep` (работа с глоб-паттернами, типами файлов, ограничением глубины поиска).
* **Этап 5: Ревизия и качество кода**
  * Проведение полного цикла проверок (`clippy`, `fmt`, `audit`).
  * Финализация `README.md` (обновление прогресс-бара до 100%).
  * Релиз финальной сборки.
